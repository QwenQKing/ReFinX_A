# ReFInX

This repository accompanies the ReFInx paper. It contains the 1,141 evaluation tasks, the refined annotations that the D1–D6 metrics read, and the evaluation framework: the agent harness, the tools, the DeepSeek-V4.1-Flash judges, the metrics and the model launch settings.

| Path | Contents |
| --- | --- |
| `data/tasks.json` | The 1,141 tasks, as one UTF-8 JSON array. |
| `annotations/refined-v1.jsonl` | Refined annotations, one JSON object per line, one line per task. |
| `refinx/` | Evaluation framework (Python package). |
| `dsh/` | DeepSeek Harness (DSH) configuration for the ReFInx agent. |
| `serve/` | vLLM launch settings and chat templates for the locally served models and the judge. |
| `tests/` | Offline tests. |
| `requirements.txt` | Python packages of the environment that ran the code. |
| `vendor/dsh/` | Installer for DSH 0.2.0-rc.2, its license, and the dependency-version inventory from the experimental environment. |

## Data

### `data/tasks.json`

The query and the reference answer are in the original language: 963 tasks are in Chinese and 178 in English.

| Field | Meaning |
| --- | --- |
| `id` | Case ID. The same ID is used in `annotations/refined-v1.jsonl`. |
| `query` | The query given to the agent, in its original wording. |
| `as_of` | Information cutoff (UTC). The tools return only material dated at or before it. This is the evaluation cutoff, not necessarily the date of an event in the query. |
| `language` | Recorded language label (`zh` or `en`). The harness uses it to choose the search language. The 222 query rewrites are labeled `en` but are written in Chinese. By-language analyses classify a query as `zh` when more than 20% of its non-space characters are CJK. |
| `source` | Source of the query: `cninfo` (741), `query_rewrite` (222), `stackexchange_finance` (141), `manifold_finance` (31), `polymarket_finance` (4), `alpaca_forum` (1) or `github_finance` (1). |
| `source_url` | URL of the original post when one exists; otherwise `null`. |
| `region` | Recorded region label (`CN`, `INTL`, `GLOBAL` or `US`). |
| `terminal_action` | Expected final action: `answer` (877) or `clarify` (264). |
| `gold_answer` | Reference answer for judging final-answer correctness (AnsAcc). |
| `accepted_alternatives` | Formulations the judge may accept in place of the reference wording. |
| `required_clarifications` | Clarifications the agent is expected to request (for `clarify` tasks). |
| `domains` | Financial domains of the task (multi-label). |
| `task_type` | Task type T1–T10 (primary deliverable). |
| `task_subtype` | Task subtype, e.g. `T6.1`. |
| `workflow_attributes` | Workflow-structure attributes: `simple`, `single_compute`, `multi_step`, `multi_tool`, `long_horizon` and `fault_sensitive`. |

### `annotations/refined-v1.jsonl`

One record per task, written in English for every task.

| Field | Meaning |
| --- | --- |
| `case_id` | Case ID. |
| `context_constraints` | Financial-context requirements an answer must respect: `kind` (`entity`, `metric`, `period`, `time`, `assumption`, `accounting_scope`, `unit_currency`) and `requirement`. Scored by CtxSat. |
| `facts` | Atomic facts the workflow must get right: `id` (F1, F2, …), `kind` (`fact` or `arithmetic`) and `statement`. Scored by FactAcc and ArithAcc. |
| `dependencies` | Cross-stage dependencies: `id` (D1, …), `relation`, `prerequisites` (fact IDs) and `requirement`. The relations are `entity`, `time`, `metric_scope`, `unit_currency`, `input_result_use` and `evidential_support`. Scored by DepCov, DepValid, LCDF and the D6 risk difference. |
| `answer_points` | Conclusions a complete answer must state: `id` (A1, …) and `statement`. Scored by ReqSat, MainSupp and the claim-support gaps. |
| `numeric_targets` | Key numbers the answer must state, each with `description`, `value`, `unit` and `tolerance`. Scored by NumAcc. Empty when no single numeric conclusion is asked for. |

The 3,693 dependencies are distributed as follows: `metric_scope` 1,036, `evidential_support` 910, `input_result_use` 860, `entity` 592, `time` 265, `unit_currency` 30.

The annotations were generated by GPT-6.1-Sol (temperature 0) with the prompt in `refinx/prompts/annotation.md`. The annotator read each task's query, cutoff, reference answer, accepted alternatives, required clarifications, and original diagnostic contract with its reference evidence. All 1,141 records passed the annotator's schema check. The annotations are model-generated and checked automatically; they have not been manually verified in full.

## Code

| Module | Role |
| --- | --- |
| `refinx/run.py` | Entry point: runs an agent model over the tasks with DSH (the default) or the built-in loop (`--harness agent`), optionally judges AnsAcc inline, and judges a finished run with `--from-run`. |
| `refinx/dsh_run.py` | Drives one task through DSH with the ReFInx overlays and records the trajectory. |
| `refinx/agent.py` | Built-in agent loop with the same limits, without DSH. |
| `refinx/tools.py`, `refinx/mcp_server.py` | The four tools, served to DSH over MCP with the task's cutoff injected: `search_web`, `get_price_history` (forward-adjusted daily prices), `get_financial_statements` (statements filtered by disclosure date) and `calculate` (exact arithmetic). |
| `refinx/judge.py` | AnsAcc judge: whether the final answer matches the reference answer, accepted alternatives and required clarifications. |
| `refinx/unit_judge.py` | Per-unit judge: a verdict for every annotation unit, the extra claims and the stated computations, from the visible trajectory and final answer. |
| `refinx/metrics.py` | D1–D6 and WRS from the latest record of each case, written to `runs/<run>/metrics.json`. |
| `refinx/context_overflow.py` | Marks tasks whose largest prompt exceeds 122,880 tokens as unobservable, for runs made with a context above 131,072 tokens. |
| `refinx/annotation.py` | The annotation schema. |
| `refinx/data.py`, `refinx/schema.py`, `refinx/net.py` | Task loading, records, HTTP and keys. |
| `refinx/prompts/` | `unit_judge.md` (per-unit judge) and `annotation.md` (the prompt that generated the annotations). |
| `dsh/refinx.patch.yml` | Turns DSH's headless profile into the ReFInx harness: the paper's system prompt, the four tools, and none of DSH's own coding, web or context tools. |
| `dsh/api.patch.yml` | For API models: thinking at the lowest setting the route offers. |
| `dsh/refinx-limits.js` | Enforces the execution limits and records the trajectory. |
| `serve/serve_model.sh` | vLLM launch settings for each locally served model and for the judge (`judge41`), with the chat templates in `serve/`. |

## Evaluation setup

- **Agent:** temperature 0, at most 8,192 output tokens per request.
- **Harness limits per task:** 240 s wall clock with a 45 s final-answer reserve, 10 model turns, 12 tool calls in total and 8 per tool, a 90 s timeout per request, and 250,000 tokens.
- **Locally served models:** vLLM on 8× H100 80 GB, one TP8 instance per model, 131,072-token context, `--generation-config vllm`.
  - Thinking is off wherever it can be set: through an official switch, or else with a chat template that prefills an empty think block.
  - Otherwise the lowest reasoning effort is used (gpt-oss: `low`), or the model's own setting where neither exists (MiniMax).
- **Context rule:** a task whose largest prompt exceeds 122,880 tokens (131,072 minus the 8,192 output tokens) is unobservable for every model. Runs made with a larger context (API models, and Qwen3.8-Flash-Next at 262,144) are marked with `refinx/context_overflow.py`.
- **Judge:** DeepSeek-V4.1-Flash, thinking on, temperature 0, served by `serve/serve_model.sh judge41` (vLLM 0.31.0). The AnsAcc judge allows 16,384 output tokens and the per-unit judge 32,768.
- **Metrics:** D1–D6 and WRS follow the paper's appendix definitions. Failure and gap rates enter WRS as 1−x, and the risk difference as 1−|RD|. ReplayAcc accepts a replayed result within half of the last stated decimal or 0.1% of the value. EM is not applicable to any task.

## External services

The tools call a web-search service and an A-share market-data service, configured through environment variables:

| Variable | Meaning |
| --- | --- |
| `REFINX_SEARCH_URL` | Search endpoint. |
| `REFINX_SEARCH_HEADERS`, `REFINX_SEARCH_BODY` | JSON objects with the service's authentication headers and extra request fields. |
| `REFINX_MARKET_DATA_URL` | Base URL of the market-data service. |
| `REFINX_MARKET_DATA_KEY` | Its API key (or the file `key_market_data.md`). |
| `REFINX_SEARCH=brave`, `BRAVE_API_KEY` | Use Brave Search instead of `REFINX_SEARCH_URL`. |

**Search.** The tool sends `POST REFINX_SEARCH_URL` with this body:

```
{"query", "channels": ["web", "news", "announcement", "report"], "size": 20, "output": "block", ...REFINX_SEARCH_BODY}
```

The service answers:

```
{"status_code": 0, "status_msg", "data": [{"title", "url", "summary" | "content", "publish_time"}]}
```

`publish_time` is in Unix seconds. Items without a date or dated after the cutoff are dropped, and at most 10 are returned.

**Market data.** Requests carry the `X-api-key` header. Times are in Unix milliseconds.

- **Prices:** `GET REFINX_MARKET_DATA_URL/prices/historical?symbol=&start=&end=&interval=1d&adjust=forward` answers `{"code": 0, "message", "data": {"item": [{"date_ms", "open_price", "high_price", "low_price", "close_price", "volume", "turnover"}]}}`.
- **Statements:** `GET REFINX_MARKET_DATA_URL/financials/{income-statements|balance-sheets|cash-flow-statements}?symbol=&period={annual|quarterly}&start=&end=` answers the same envelope. Each item has `period_end_ms`, `report_date_ms` and the statement's line items.

## Running an evaluation

Serve a test model, then run the agent without inline judging. For API models, set `REFINX_LLM_BASE_URL` to the OpenAI-compatible endpoint and add `--provider api`; use `REFINX_REASONING_OFF=none` when the route accepts `reasoning_effort`. Apply the context-overflow step only to runs with a context above 131,072 tokens. Next serve the judge, judge final-answer accuracy, and run the per-unit judge twice so that the second pass retries invalid outputs. The last command writes the metrics to the run directory.

```bash
MODEL_DIR=/path/to/weights PY_0_29=/path/to/vllm-0.29/bin/python serve/serve_model.sh qwen38-27b
export REFINX_LLM_BASE_URL=http://127.0.0.1:3800/v1

python -m refinx.run --harness dsh --agent-model Qwen3.8-27B --sample 1141 --seed 0 --workers 32 \
  --name full-qwen38-27b --resume --skip-judge
python -m refinx.context_overflow runs/full-qwen38-27b

VLLM_0_31=/path/to/vllm-0.31/bin/vllm serve/serve_model.sh judge41
export REFINX_LLM_ENDPOINT=http://127.0.0.1:3800/v1/chat/completions
python -m refinx.run --from-run full-qwen38-27b --name full-qwen38-27b-judged-v41 \
  --judge-model deepseek-v4.1-flash-judge --workers 32

python -m refinx.unit_judge --run full-qwen38-27b-judged-v41 --annotations refined-v1 \
  --judge-model deepseek-v4.1-flash-judge --workers 32 --resume

python -m refinx.metrics --run full-qwen38-27b-judged-v41 --annotations refined-v1
```

**Keys:** each key is read from an environment variable, or else from a file in `REFINX_KEY_DIR` (default: the repository root; `key*.md` is git-ignored):

| Purpose | Variable | File |
| --- | --- | --- |
| Agent, judge and API-model endpoint | `REFINX_LLM_API_KEY` (a local vLLM needs none) | `key.md` |
| Market data | `REFINX_MARKET_DATA_KEY` | `key_market_data.md` |
| Brave Search (optional) | `BRAVE_API_KEY` | `key_search.md` |

Run the tests with `python -m pytest tests` or `python -m unittest discover tests`.

## Dependencies

These versions were used in the experiments on 8× NVIDIA H100 80 GB (Ubuntu 24.04, driver 550.54.15, CUDA 13.0).

| Component | Version | Used for |
| --- | --- | --- |
| Python | 3.12.3, packages pinned in `requirements.txt` (`mcp` 1.16.0, `pydantic` 2.12.3 and their dependencies) | The `refinx` code and the MCP tool server. `refinx` itself uses only the standard library. |
| Node.js | 25.9.0 | Runs DSH. |
| DSH (`@deepseek-ai/dsh`) | 0.2.0-rc.2, installed from npm with `vendor/dsh/install.sh` | The agent harness. |
| vLLM | 0.31.0 (torch 2.13.0+cu130, transformers 5.17.0) | The judge, DeepSeek-V4.1-Flash, Ling-3.0-flash-Fin, MiniMax-M2.1/M2.5/M2.7 and Qwen3.6-35B-A3B. |
| vLLM | 0.29.0 (torch 2.13.0+cu130, transformers 5.17.0) | The other locally served models. |
| vLLM | 0.29.1rc1.dev439+g967917378 | GLM-5.3-Flash. |

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
bash vendor/dsh/install.sh "$HOME/.refinx-node/global"
export PATH="$HOME/.refinx-node/global/bin:$PATH"
```

Node.js 25.9.0 must be on `PATH`. Installing DSH requires network access to npm. The installer pins DSH itself; `vendor/dsh/packages.tsv` records the dependency versions used in the experiments, while a new npm installation may resolve different transitive dependency versions. The chat templates in `serve/` are derived from the corresponding models' templates; the GLM and Step templates prefill an empty thinking block.
